# Bybit Realtime Chart + OU Demo Trader

Приложение для **мониторинга свечей Bybit в реальном времени** (Spot и Linear Futures с переключением на лету) с построением графика, линии справедливой цены (**фильтр Калмана**), сигналов **mean reversion на процессе Орнштейна–Уленбека (OU)** и **демо-торговлей** (эмуляция сделок по сигналам OU с виртуальным балансом и настраиваемым плечом для фьючерсов).

---

## Что делает программа

1. Загружает последние **100 минутных свечей** через REST API Bybit.
2. Подключается к **WebSocket** и получает live-обновления текущей свечи.
3. Строит интерактивный график: **свечи**, **объём**, **SMA 5/10**, **линия Калмана**, z-score в подсказке.
4. На каждой **закрытой** свече считает спред `close − fair_price` и обновляет **OU-модель** (z-score, сигнал BUY/SELL/FLAT/STOP).
5. По сигналам OU работает **демо-трейдер**: виртуально открывает и закрывает позиции (maker/taker-исполнение, комиссии, проскальзывание, плечо, стопы по цене и по z-score), сделки отображаются маркерами на графике.
6. Позволяет **переключать торговый режим** Spot ↔ Futures прямо из веб-интерфейса — у каждого режима своя изолированная сессия (свечи, индикаторы, баланс, история сделок) и свой файл состояния.
7. Для фьючерсов — **ползунок плеча** (1x–10x) в веб-интерфейсе.
8. Отображает статус OU и статистику демо-трейдера в веб-интерфейсе.
9. Отправляет обновления в браузер через **Socket.IO** без перезагрузки страницы.

Пока минута не закрыта — свеча меняется по данным биржи. Когда приходит `confirm: true` — свеча фиксируется, фильтр Калмана, OU и демо-трейдер делают по одному шагу.

> ⚠️ Демо-трейдер **не отправляет ордера на биржу** — это симуляция с виртуальным балансом в USDT.

### Потоки

- **Главный поток** — Flask/SocketIO (порт `5000`)
- **Фоновый поток** — WebSocket-клиент к Bybit (asyncio)
- Чтение свечей, оценок Калмана, z-score и статусов — под `RLock` в `data_collector` (атомарный `get_render_data()`)

### Торговые режимы

- Два режима: **Spot** (`category=spot`, WS `public/spot`) и **Futures** (`category=linear`, WS `public/linear`)
- Каждый режим получает собственный `MarketSession`: свечи, Калман, OU, Z-история, DemoTrader с отдельным балансом и файлом состояния
- Переключение выполняется через `POST /api/market/switch`: сохраняется DemoTrader текущего режима, сбрасывается история индикаторов, WS переподключается к новому эндпоинту, история нового режима загружается через REST
- Для фьючерсов доступно плечо 1x–10x (`POST /api/market/leverage`); для спота плечо всегда 1x

### Логика демо-трейдера

**Вход**

- Сигнал OU `BUY` при `z ≤ -entry_z`, `SELL` при `z ≥ +entry_z`.
- Если включён maker-режим (`DEMO_MAKER_ENABLED`), выставляется лимитный ордер на отступе `DEMO_MAKER_OFFSET` от цены закрытия. Он исполняется, когда цена касается лимита (`low ≤ limit` для BUY, `high ≥ limit` для SELL), и живёт не дольше `DEMO_MAKER_TIMEOUT_CANDLES` свечей, после чего отменяется.
- Если maker выключен (или вход идёт по legacy-цене), позиция открывается мгновенно как taker с проскальзыванием.

**Выход** (проверяется по приоритету)

1. **Ликвидация** (только при плече > 1x) — по `high`/`low`, если цена достигла расчётного уровня `entry ∓ margin / amount`; баланс не уходит в минус.
2. **Hard stop по цене** — движение против позиции на `DEMO_PRICE_STOP_PCT` (по `high`/`low`).
3. **Trailing stop по цене** — после выхода в прибыль закрытие при откате от лучшей цены на `DEMO_PRICE_TRAILING_PCT`.
4. **Hard stop по z** — `|z| ≥ stop_z`.
5. **Exit target** — `|z| ≤ exit_z`.
6. **Trailing stop по z** — после приближения `|z|` к нулю закрытие при откате на `trailing_reversal_z`.
7. **Time stop** — удержание дольше `DEMO_MAX_POSITION_MINUTES` минут.

**Прочее**

- Объём позиции — доля баланса (`position_size_pct`) × плечо; маржа считается как `balance × position_size_pct`, комиссии вход/выход вычитаются из PnL, поэтому `balance − initial_balance = total_pnl` (сходится, включая комиссию входа).
- Состояние (баланс, сделки, открытая позиция, висящий лимитный ордер) сохраняется в JSON-файл режима (`demo_trader_state_spot.json` / `demo_trader_state_futures.json`) и восстанавливается при перезапуске.
- Сброс демо-счёта — кнопка в веб-интерфейсе (`POST /api/demo/reset`).

## Как определяется закрытие свечи

Bybit присылает в push-сообщении kline поле **`confirm`**:

- `false` — свеча ещё формируется
- `true` — минута закрыта, OHLCV финальные

Ключ свечи — поле **`start`** (время открытия минуты), а не `timestamp` (время последней сделки).

Дополнительно: если новая свеча началась, а `confirm` по предыдущей не пришёл (потеря пакета), предыдущая свеча финализируется принудительно — Калман и OU всегда делают ровно один шаг на закрытый бар. Повторные `confirm` одной и той же свечи игнорируются.

## Веб-интерфейс

- **График**: свечи с z-score в подсказке (hover), SMA 5/10, объём, жёлтая линия Калмана
- **Маркеры сделок**: треугольники — входы (▲ BUY / ▼ SELL), круги — выходы (цвет по PnL), открытая позиция выделяется жёлтой обводкой
- **Переключатель режима**: кнопки Spot / Futures — смена торгового режима без перезапуска
- **Ползунок плеча**: 1x–10x (активен только для фьючерсов)
- **OU-статус**: z-score, сигнал, готовность модели
- **Панель демо-трейдера**: баланс, общий PnL, комиссии, число сделок, winrate, открытая позиция, кнопка сброса, список последних сделок
- **Статистика 24ч**: high, low, volume

## Результаты

- Live-график минутных свечей Bybit, согласованный с данными биржи
- Переключение Spot ↔ Futures на лету с изолированным состоянием каждого режима
- Настраиваемое плечо (1x–10x) для фьючерсов
- Обновление текущей свечи до закрытия минуты
- Линия справедливой цены (Калман) — один шаг на каждую **закрытую** свечу
- OU-стратегия mean reversion: z-score (относительно равновесного `mu`) и сигнал (BUY / SELL / FLAT / STOP) на спреде `close − Kalman`
- Демо-торговля по сигналам OU: maker/taker-входы, виртуальный баланс, комиссии, проскальзывание, плечо, стопы по цене/z и ликвидация
- Сохранение и восстановление состояния демо-трейдера между запусками (отдельно для каждого режима)
- Автопереподключение WebSocket при обрыве связи
- Статистика 24ч (high, low, volume) в интерфейсе

## Ограничения

- Рынки **Spot** и **Linear (USDT) Futures** — без Inverse и Options
- Подписка на **kline**, не на order book и не на поток каждой сделки
- Kline push от Bybit — с интервалом ~1–60 сек, не на каждое изменение стакана
- Калман, SMA и OU — дополнительные индикаторы; на стандартном UI Bybit их нет
- OU, Калман и демо-трейдер обновляются только на **закрытых** свечах, не внутри формирующейся минуты
- Демо-трейдер — **симуляция**: реальные ордера на биржу не отправляются
- Плечо в демо-режиме моделирует изолированную маржу и ликвидацию по расчётной цене, но не учитывает поддерживающую маржу и фандинг; ликвидация возможна только при гэпе через стопы по цене
- z-score считается относительно равновесного среднего OU (`mu`), а не нуля спреда: если линия Калмана систематически смещена, `mu ≠ 0` и пороги отрабатывают асимметрично
- Статистика 24ч загружается при старте (и при смене режима) и не обновляется в реальном времени
